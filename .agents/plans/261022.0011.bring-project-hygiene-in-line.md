## Decisions

Each decision lists its reason and its reversal path.

1. **`dsl` stays a direct requirement of the root module; accept its node in consumers'
   module graph.** The two alternatives (nested module, `ignore` build tag) break ruleguard,
   verified above. The footprint on consumers is a module-graph entry with no checksum, no
   download, and no code in their builds — the same exposure testify already has. Reversal:
   when a ruleguard release resolves `dsl` internally, tag the file `//go:build ignore` and
   run `go mod tidy`; the `make lint` probe in Task 1 tells whether rules still load.
2. **golangci-lint pin lives only in `Makefile` (`GOLANGCI_VERSION := v2.15.0`).** CI installs
   it with `make lint-install`; the workflow never names a linter version. 2.15.0 is the
   locally installed version and is clean on `main`. On a version mismatch `make lint` exits 1
   when `$CI` is set and only warns (stderr) otherwise: a Homebrew upgrade must not block
   local work, while CI must never lint with an unpinned version. Reversal: drop the `$CI`
   condition (hard failure everywhere) or the check.
3. **`make test` runs only the race suite with `CGO_ENABLED=1`; formatting is never a
   dependency of a check.** The no-cgo proof moves to its own target (`build`, plus `vet`
   under `CGO_ENABLED=0`). Reversal: none needed; `make format` remains for humans.
4. **`make verify` is the single gate, locally and in CI:** `fmt-check tidy-check vet build
   lint lint-selftest test`, cheapest first. Reversal: edit the prerequisite list.
5. **`lint-new` and `LINT_BASE` are removed.** They were the adoption gate while standing
   findings were worked off; plan 261021.0007 cleared them, the whole tree is clean, and no
   plan or doc references the target. Reversal: restore the target from git history.
6. **CI: two jobs on `ubuntu-24.04`.** `verify` runs `make lint-install && make verify` on a
   pinned Go minor (`1.27.x`, matching `mac-m1`), so a new Go release cannot turn CI red
   without a change. `floor` runs `make test` and `make build` with `go-version-file: go.mod`
   and `GOTOOLCHAIN=local`, proving the declared `go 1.22.2` floor. Reversal: switch
   `verify` to `go-version: stable`, or drop `floor` if the floor is raised to the
   toolchain.
7. **Plan-reference regex matches the plan id itself** (`YYMMDD.NNNN`, bounded by
   non-digit/non-dot characters), keeps the legacy `plans/NNN-` form and the existing
   `PLAN-n`/`task #n` forms, and the scan adds `*.sh`, `*.yml`, `*.yaml`, and `Makefile`.
   The self-test generates its fixtures at runtime in a temp directory, so no committed file
   carries a violating string. Reversal: narrow the include list.
8. **`AGENTS.md` becomes a map (target text in Task 8, 4297 bytes measured after review round 1).**
   Exhaustive API enumerations are replaced by a path map and pointers to the declaring
   files; only non-obvious tripwires stay. Redaction is described by its invariants and
   pointed at `httptap/redact.go`, not by listing the header names, so 0009-style changes do
   not make it false again. Reversal: none; detail lives in godoc.
9. **No CHANGELOG `[Unreleased]` entry for this plan.** Nothing here changes what consumers
   build or observe (the `go.mod` change only moves `dsl` between `require` blocks). Only the
   link references are fixed. Reversal: add a `Changed` bullet if a reviewer finds a
   consumer-visible effect.
10. **`httptap/doc.go` example is fixed in the comment**, not converted to a compiled
    `Example` test. A compiled example would prevent recurrence but adds a test file outside
    this plan's no-behaviour scope; recorded as a follow-up backlog entry in Task 9.
    Reversal: the follow-up.
11. **Release numbering follows the owner's recorded stance** (orchestrator decision,
    plan review round 1, based on owner memory `versioning-stance`): the 1.0.x line is
    pre-stable; next version = latest tag + PATCH, regardless of `Added` or breaking
    entries; breaking changes are documented in the CHANGELOG `BREAKING CHANGES` section
    (as in `[1.0.6]`). Reason: a `v1.0.0` was published by accident and cannot be withdrawn,
    every consumer is in-house and pinned, and `/v2` module-path churn across the consumer
    fleet was rejected by the owner. Reversal: when the owner declares the API stable,
    replace the release bullet with SemVer bumps (breaking → major via `/vN`, `Added` →
    minor, else patch).

## Trade-offs

- Chose keeping `dsl` in the root `go.mod` over a nested module or an `ignore` build tag,
  because both alternatives break ruleguard (verified) and the consumer footprint is a
  checksum-free graph node.
- Chose a warning over a hard failure on a local linter version mismatch, because CI
  installs the pin and a local hard failure would block work after every Homebrew upgrade.
- Chose pinning CI Go to `1.27.x` over `stable`, because an unannounced Go release adding
  vet checks would turn unrelated PRs red; the cost is a manual bump.
- Chose GitHub-hosted runners over `ci-runner-01`, because the runner refuses public and
  personal-account repositories; this repository is both.
- Chose one plan for all hygiene items over one plan per item, because they share the
  gate, the branch, and the docs facts; Decision boundaries keep each item reviewable.
- Chose describing redaction by invariant and pointing at `httptap/redact.go` over listing
  header names in `AGENTS.md`, because a list is a copy of code and went stale once already.
