# Keep file handler descriptors open between writes

- raised: 2026-10-22 — deferred by plan 261022.0010 (finding #9 of the 2026-10-22 project review)
- decision: open

`RotatingFileHandler` and `FileByFormatHandler` open, write, and close the file for every line. Plan 261022.0010 coalesced the two writes into one; keeping the descriptor open was deferred because it changes behaviour under external log management (after a `logrotate` rename, writes continue into the renamed file; after an external `rm`, writes go to an unlinked inode; after `copytruncate`, the size counter is wrong), and the handlers have no `Close` in their API, so a cached descriptor would leak for the process lifetime and block the stable-name rename on Windows.

Before any design: a benchmark showing the gain on the target filesystems. If pursued, use an opt-in shape (for example a new `RotatingFileOption`) that leaves the default path-following behaviour intact.
