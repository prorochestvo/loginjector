# Take per-event locks out of the Axiom worker loop

- raised: 2026-10-28 — deferred by plan 261021.0006 (architecture review, P3)
- decision: open

For every event it receives, the Axiom worker takes `errorMu` (through `reportDrops`) and `mu.RLock`. The RLock contends with producers' RLocks on the same cache line, while the plan only requires a drop check on each ticker tick. Proposal: keep `closed` in an `atomic.Bool` that is still written under `mu.Lock`, and call `reportDrops` only on the ticker and on exit. A contention benchmark should show the gain first.
