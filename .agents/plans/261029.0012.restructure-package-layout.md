# Task Breakdown

- source: owner feedback `feetback-20261028.md` (main checkout, owner-owned, not copied here)

## Overview

Restructure `github.com/prorochestvo/loginjector` into a small core and opt-in packages:
the root keeps the fan-out logger and error types; sink factories move to `extensions`;
the Axiom implementation moves to `internal/integrations/axiom` behind a facade in
`extensions/axiom.go`; closers and the level ladder move to `adapters`; the HTTP
access handler moves to `extensions/http.go`; the ruleguard rules move to
`configs/linter/custom-rules.go`. This is a hard breaking change with no root forwarders
(forwarders would make the root import `extensions`, which imports the root: a cycle).
It ships as v1.0.10 under the pre-stable 1.0.x policy, with a `BREAKING CHANGES`
section and an old-to-new migration table in `CHANGELOG.md`.

Target layout (owner decision, with the deviations listed at the end):

```
loginjector/                     logger.go, error.go (+ internal stack-trace helpers)
extensions/                      doc.go, file.go, file_unix.go, file_other.go, print.go,
                                 tbot.go, http.go, axiom.go
adapters/                        doc.go, closers.go, levels.go
httptap/                         payload and recover middleware (access leaves)
internal/sink/                   NEW: guarded func writer + timestamped renderer
internal/httpx/                  NEW: response-writer composition + path escaping
internal/integrations/axiom/     the whole Axiom implementation
internal/, internal/synctest/    unchanged
configs/linter/custom-rules.go   ruleguard rules (was gorules/rules.go)
```

Import graph after the change (arrows = "imports"; must stay acyclic):

```
root                    -> internal, internal/sink
adapters                -> root
internal/httpx          -> stdlib only
internal/integrations/axiom -> root, adapters
httptap                 -> root, internal/httpx
extensions              -> root, internal/sink, internal/httpx, internal/integrations/axiom
```

Invariant: the root and `internal/sink`, `internal/httpx`, `internal` (stack trace),
`internal/synctest` never import `adapters`, `extensions`, `httptap`, or
`internal/integrations/...`. No non-test package imports `extensions`.
`internal/integrations/axiom` imports `adapters` (see Decision C4).

## Decisions on the known couplings

**C1 — the root-private `*writer` (logger.go:372, :409, handler.go:1137-1160).**
Factories in `extensions` cannot build a root `*writer`. Split the two roles the type
plays today:
- *Self-guarded factory writer* (`h` set, `original` nil): becomes
  `internal/sink.Func`, a mutex-guarded func writer with only `Write`. Every factory
  (`extensions` and the root default) returns `*sink.Func`.
- *Registration wrapper* (`original` set, optional `shared` mutex, `WriteLevel`
  forwarding): stays the root-private `*writer`, built only by `ensureThreadSafe` and
  `WriterAs`, unchanged.

The root recognises `*sink.Func` exactly where it recognises `*writer` today as
"already self-serialised": `ensureThreadSafe` returns it unchanged and `sinkIdentity`
returns `(nil, false)` for it. `unwrapLeveled` and `writeSink` need no change (a factory
writer has no `original` and no `WriteLevel`; today its `WriteLevel` falls through to
`h(p)`, which is what `writeSink` does by calling `Write`). `sinkTypeName` needs no new
case: a `*sink.Func` is reported as `*sink.Func` (today: `*loginjector.writer`).
Per-sink serialisation, the shared mutex per pointer identity, panics-as-errors, and the
leveled gate are untouched. Reversal: fold `sink.Func` back into a root type when the
factories return to the root.

Rejected: (a) let the root wrap every factory writer like any pointer sink — works, but
double-locks every write and changes `sinkIdentity` behaviour for no gain; (b) export a
root constructor for `*writer` — new public API whose only purpose is internal plumbing;
(c) move `writer` itself to `internal` — its `WriteLevel` needs `LogLevel` and
`LevelWriter`, which live in the root, and `internal` cannot import the root.

**C2 — the default handler in `NewLogger` (logger.go:81).** The renderer behind
`newTimestampedWriter` moves to `internal/sink.NewTimestamped(out, layout, clock)`, with
`sink.DefaultTimeLayout = "2006/01/02 15:04:05"`. `NewLogger` calls
`sink.NewTimestamped(os.Stdout, sink.DefaultTimeLayout, time.Now)`;
`extensions.TimestampedHandler`/`TimestampedPrintHandler` call the same function with
their resolved `printConfig`. One implementation, no duplication; `PrintOption`,
`printConfig`, `withClock` stay in `extensions/print.go` (their only consumer).

**C3 — `WithMinLevel` stays in the root (deviation).** The leveled gate works through
the `LeveledHandler` interface, but two root mechanisms need the concrete type:
`sinkIdentity` peels `*leveledWriter` so that `buf` and `WithMinLevel(x, buf)` share one
mutex (documented in the `NewLogger` godoc "Covered" list and the AGENTS.md tripwire,
tested in `TestNewLoggerForRaceCondition` "buffer and WithMinLevel of the same buffer"),
and `sinkTypeName` peels it to report the user sink in panic errors (asserted as
`*loginjector.leveledWriter` in `logger_test.go:860`). From `extensions` the root cannot
see the type; keeping the guarantee would need a new public unwrap contract
(`Unwrap() io.Writer`) recognised by the root. The interface contract therefore does not
make the move work, so `WithMinLevel` and `leveledWriter` move from `handler.go` into
`logger.go`. It is pure composition with no I/O, which also fits the core. Reversal: add
an exported `Unwrap() io.Writer` convention to the root and move it.

**C4 — `levels` imports the root.** `adapters/levels.go` imports the root for
`LogLevel`; the root and `internal/sink`, `internal/httpx` never import `adapters` or
`extensions` (verified in Task 11). `internal/integrations/axiom` keeps its default
level name `levels.Name` as `adapters.Name`, so it imports `adapters`; the graph stays
acyclic (`adapters` imports only the root). Injecting the default from the facade instead
would leave the internal handler without a default for its own tests and constructor.
Reversal: move the default into `extensions.NewAxiomHandler` by prepending
`axiom.WithLevelName(adapters.Name)` to the options.

**C5 — `httptap/access.go` helpers.** The shared helpers move to `internal/httpx`,
exported inside `internal` only:
- `httpx.Tap` (was `tapWriter`): `http.ResponseWriter` + `MarkHijacked()` +
  `BeforeFlush()`; the seven composite types (`flusherRW` ... `allThreeRW`) and
  `httpx.WrapWithOptionalInterfaces(base Tap, w http.ResponseWriter)`;
- `httpx.IsInformational(code int) bool`;
- `httpx.EscapeControl(s string) string` (with its unexported helpers).

`httptap`'s `interceptor` and `recoverResponseWriter`, and the access writer, rename
`markHijacked`/`beforeFlush` to `MarkHijacked`/`BeforeFlush`. These are exported methods
on unexported types: no new identifier appears in `httptap`'s or `extensions`' godoc.
They are reachable by a type assertion on the wrapped `http.ResponseWriter` a handler
receives; calling them only corrupts that request's own log bookkeeping. Rejected:
passing callbacks instead of an interface (keeps the methods unreachable but allocates two
method-value closures per request and rewrites every composite type). Reversal: switch
`WrapWithOptionalInterfaces` to a callback struct. The always-on redaction sets stay in
`httptap/redact.go`, untouched; `EscapeControl` moves byte-for-byte with its test.

  keep their names, subtests, `t.Parallel()` calls, and `//nolint:paralleltest // reason`

    ```go
    // Func is a mutex-guarded writer over a write function; concurrent Write calls run
    // one at a time.
    type Func struct {
    	m     sync.Mutex
    	write func(p []byte) (int, error)
    }

    // NewFunc returns a Func that serialises calls to write.
    func NewFunc(write func(p []byte) (int, error)) *Func { return &Func{write: write} }

    // Write calls the write function while holding the writer's mutex.
    func (f *Func) Write(p []byte) (int, error) {
    	f.m.Lock()
    	defer f.m.Unlock()
    	return f.write(p)
    }
    ```

## Risks

- **Consumer breakage.** Every in-house consumer that upgrades past v1.0.9 must rewrite
  imports. Mitigation: the CHANGELOG table is complete and mechanical (the symbol names
  outside Axiom do not change, only their package), so a consumer migrates with
  `goimports` plus a find-and-replace of the qualifiers.
- **Alias docs.** `go doc`/pkg.go.dev show `type AxiomHandler = axiom.Handler` without the
  method set of the internal type. Mitigation: the alias comment and the package doc list
  the methods (Task 10).
- **Lost history.** The squash merge keeps rename detection only for files moved whole;
  `handler.go` and `handler_test.go` appear as deletions. Mitigation: the PR body lists
  where each `handler.go` symbol went (the symbol map).
- **Reachable `MarkHijacked`/`BeforeFlush`.** See C5; worst case is one request's log
  line misreporting its status.
- **Large test file.** `extensions/file_test.go` merges four files (about 3,000 lines).
  It mirrors `file.go` as the owner's rule requires; splitting it again would break R17.
- **`${base-path}` support.** Covered by the Task 1 probe and fallback.

## Trade-offs

- Chose `internal/sink.Func` for factory writers over letting the root wrap them like
  user sinks, because it keeps today's single lock per write and today's identity rules;
  reversal: delete `sink.Func`, return plain structs, and let `ensureThreadSafe` wrap.
- Chose to keep `WithMinLevel` in the root over an exported `Unwrap()` contract, because
  the shared-mutex guarantee depends on the concrete type and a new public contract is a
  larger change than the move it would enable (C3).
- Chose the `Axiom` infix on every exported Axiom name (`NewAxiomHandler`,
  `WithAxiom*`, `Axiom*` types, `ErrAxiomClosed`) over renaming only the colliding ones,
  because `extensions` holds four option families and a partial prefix leaves names such
  as `WithFields` or `WithCompression` ambiguous next to `WithCompress` and
  `WithFileCompression`; reversal: rename in `extensions/axiom.go` only.
- Chose forwarding funcs over `var WithAxiomX = axiom.WithX`, because funcs carry their
  own doc comments and cannot be reassigned by a consumer; `ErrAxiomClosed` is a var
  because sentinel identity requires the same value.
- Chose to copy the small test fakes and `uniqueToken`/`captureStdout` per package over a
  shared test package, following the owner's split decision and keeping each package's
  tests free to diverge.
- Chose `loginjector:` as the panic prefix in `extensions.NewAccessHandler`, matching the
  other `extensions` error strings, over keeping a now-wrong `httptap:` prefix.
- Kept the owner's names `adapters.Parse`/`adapters.Name` as decided; the level context
  previously carried by the package name `levels` is now carried by the doc comments only.
