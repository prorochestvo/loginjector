# Task Breakdown

## Overview

The 2026-10-22 project review (main @ 434ed68) found two groups of defects in
`httptap/`. First, the always-on redaction contract is weaker than documented: header
redaction compares keys case-sensitively (a handler writing `w.Header()["set-cookie"]`
directly leaks the cookie, C3), the default set misses common API-key headers, query-string
credentials are logged verbatim (11), and the decoded URL path is written raw, so `%0A`
in a request path forges log lines in the access, payload, and summary output (12).
Second, the response-writer wrappers disagree with `net/http` about what was actually
sent: `NewRecoverHandler` forwards `Flush` to the real writer while bypassing its own
buffer, so `WriteHeader(404)` + `Write` + `Flush` sends 200 and a panic after `Flush` never
sends 500 (2); access and recover treat 1xx informational responses as final (C5);
recover drops header deletions (C6) and does not freeze headers at `WriteHeader` (C8); the
payload interceptor records the last attempted status instead of the committed one
(C9/21); and `NewAccessHandler` logs `[000]` for a handler that returns without writing,
although `net/http` sends an implicit 200 (10).

This plan makes redaction strictly stronger and aligns every wrapper's view of status,
headers, and flushing with `net/http`, without breaking the public API and keeping the
`Flusher`/`Hijacker`/`Pusher` composite pass-through working.

## Assumptions

- Scope is `httptap/` production code, its tests, and `CHANGELOG.md` `[Unreleased]`.
  Logger core, file handlers, Telegram, and human docs (`README.md`, `AGENTS.md`) are out
  of scope (see Risks for the doc follow-up).
- Go floor stays `go 1.22.2`: the `clear` builtin and the `maps` package (Go 1.21) are
  available. Dependencies stay stdlib + testify.
- Versioning stance (owner memory): 1.0.x is pre-stable; behaviour changes are recorded
  in the CHANGELOG, not avoided. Release numbering is decided at release time, not here.
- `httptest.ResponseRecorder` treats every `WriteHeader` code, including 1xx, as final
  (`net/http/httptest/recorder.go`), while the real server writes 1xx except 101
  immediately and keeps waiting for the final status (`net/http/server.go`, `code >= 100
  && code <= 199 && code != StatusSwitchingProtocols`). 1xx tests therefore need a
  test fake that records every `WriteHeader` call; the recorder is still used for
  final-status, snapshot (`Result().Header`), and trailer (`Result().Trailer`) assertions.
- `ResponseRecorder.Flush` commits an implicit 200 when no header was written; that is
  the property the item-2 regression tests rely on. The existing `fakeFlusherWriter`
  overrides `Flush` and hides this, so new tests use a plain `httptest.NewRecorder()`.
- Other plans are being written concurrently (lint findings S1/S2 touch

  `AGENTS.md`). This plan does not do that work; the implementer rebases over it.
- No owner-feedback file is open in `.agents/plans/`.

## Decisions

Each decision lists its reason and its reversal path.

1. **Header redaction compares case-insensitively by lowercase folding**, not by
   `http.CanonicalHeaderKey`. `CanonicalHeaderKey` returns keys containing non-token
   characters unchanged, so it is not a full fold. Both the configured set and the logged
   key are normalised with `strings.ToLower(strings.TrimSpace(k))`. The logged line keeps
   the key as the handler spelled it. Reversal: switch the normaliser back; the set is
   internal.
2. **Default header set gains `X-Api-Key` and `X-Auth-Token`.** This is a behaviour
   change (those headers disappear from payload logs and cannot be restored, because the
   default set is not removable), but it strictly strengthens the documented security
   contract, and both names carry credentials by convention. Others (`X-Csrf-Token`,
   vendor-specific tokens) are left to `WithRedactHeaders`. Reversal: drop the two
   entries; CHANGELOG note.
3. **Query parameters are redacted by masking the value, not by dropping the parameter.**
   The logged request line keeps `name=[REDACTED]` so the request shape stays debuggable;
   headers keep their existing omit-the-line behaviour. Matching is case-insensitive on
   the percent-decoded name; segments are split on both `&` and `;`, because some
   backends treat `;` as a separator and a missed separator would leak. Non-matching
   segments are emitted byte-for-byte; with no match the query is byte-identical.
   Reversal: change the mask function; internal.
4. **Query redaction has an always-on default set**, mirroring the header contract:
   `access_token` (RFC 6750 §2.3 defines it as a query parameter), `refresh_token`,
   `id_token`, `client_secret`, `api_key`, `apikey`, `password`. Ambiguous names (`token`,
   `key`, `code`, `sig`, `signature`) stay out of the default set and are added through the
   new additive option `WithRedactQueryParams(names ...string) PayloadOption`. Reversal:
   shrink the set; CHANGELOG note.
5. **Log-injection defence is minimal percent-encoding of control characters** (bytes
   `0x00`–`0x1F`, `0x7F`, and the UTF-8 forms of U+0085, U+2028, U+2029) in the logged
   path and query. A string without those bytes is returned unchanged, so normal paths —
   including non-ASCII ones such as `/café` — log byte-identically. `URL.EscapedPath()`
   was rejected: it would re-encode every non-ASCII path and change existing output. A
   literal `%0A` in the original path and an encoded newline render alike; this is an
   accepted ambiguity, not an injection. Reversal: extend the escaped byte set; internal.
6. **`Flush` through `NewRecoverHandler` commits the buffered response.** A handler that
   calls `Flush` asks for bytes on the wire now, so the buffered status, headers, and body
   are forwarded, then the real `Flush` runs, and the writer switches to pass-through.
   After that point the response cannot be replaced; a later panic is logged and the
   handler re-panics with `http.ErrAbortHandler`, which makes `net/http` abort the
   connection (HTTP/1) or reset the stream (HTTP/2) — the same outcome as a panic after
   a write without middleware. Returning silently was rejected: the server would finish
   the chunked encoding cleanly and the client would accept a truncated body as complete.
   Making `Flush` a buffered no-op was rejected: it keeps the 500 guarantee but leaves
   SSE/streaming handlers hanging until return, and the current code already advertises
   `http.Flusher`. Reversal: make `beforeFlush` a no-op for the recover writer and stop
   calling the real `Flush` (separate behaviour change).
7. **One internal flush hook serves all three wrappers.** The unexported interface
   `hijackMarker` (`httptap/rw.go`) is renamed `tapWriter` and gains `beforeFlush()`.
   Every composite `Flush` calls `base.beforeFlush()` and then the real flusher. The
   access writer and the interceptor record an implicit 200 commit there; the recover
   writer commits its buffer. The base itself never implements `http.Flusher`, so the
   default (no optional interface) case of `wrapWithOptionalInterfaces` still returns a
   writer that does not advertise `Flusher`. Reversal: internal rename only.
8. **Committed-status rule for the access writer and the interceptor:** the first final
   `WriteHeader` (any code outside 100–199, or 101), the first `Write` (implicit 200), or
   the first `Flush` (implicit 200) commits the status; later `WriteHeader` calls do not
   change the recorded status. 1xx except 101 are forwarded immediately and never
   recorded. Reversal: none needed; this is `net/http`'s rule.
9. **`NewAccessHandler` status when nothing was written:** `[200]` when `next` returned
   normally (implicit 200), `[000]` when the connection was hijacked or `next` panicked
   before committing a status. Panic detection uses a completion flag set after `next`
   returns, not `recover()`, so the panic and its stack propagate untouched. Reversal:
   drop the completion flag (panics would then log `[200]`, which is wrong).
10. **Recover header semantics follow `net/http`:** the header map seen by `next` stays
    one stable buffered map; the final `WriteHeader` freezes a snapshot; on commit the
    real header map is *replaced* by the snapshot (deletions applied); after the
    response is written, trailer entries (keys declared in the snapshot's `Trailer`
    header, and keys with `http.TrailerPrefix`) are copied from the live buffered map to
    the real map so `net/http` sends them as trailers. 1xx responses are forwarded at
    once with the buffered headers applied temporarily and the real map restored
    afterwards, so a later 500 does not inherit handler headers such as
    `Content-Length`. Reversal: internal.
11. **A second final `WriteHeader` keeps each wrapper's current forwarding behaviour**,
    and the split is documented rather than unified: the interceptor forwards it (the
    real writer reports the superfluous call, as without middleware); the access writer
    swallows it (unchanged, its godoc already says so); the recover writer swallows it
    before commit (nothing has reached the real writer yet) and forwards it after commit
    (the real writer has the committed status and reports the superfluous call). None of
    the three records the second code. Unifying was rejected as a behaviour change with
    no defect behind it: the only observable difference is whether `net/http` prints its
    "superfluous WriteHeader" warning. Reversal: forward in the access writer.

## Tasks

### Task 1: Make header redaction case-insensitive for any key spelling (C3)

- Description: `headerToStringWithRedact` (`httptap/redact.go`) looks the raw map key up in
  a canonical-keyed set, so a non-canonical key written straight into the map
  (`w.Header()["set-cookie"] = ...`, `r.Header["authorization"]`) is logged. Normalise both
  sides per Decision 1:
  - `defaultPayloadConfig` (`httptap/payload.go`) and `WithRedactHeaders` store
    `strings.ToLower(strings.TrimSpace(name))` in `payloadConfig.redactHeaders`; update
    the field comment ("case-canonicalised via http.CanonicalHeaderKey") accordingly.
  - `headerToStringWithRedact` looks up `strings.ToLower(key)` after the existing
    `TrimSpace`; it still writes the original key to the log line. Update its godoc
    (the "keys sourced from an http.Header are always canonical" claim is false).
  - Add a small unexported helper `redactKey(name string) string` in `redact.go` used by
    both places, so the normalisation exists once.
- Acceptance Criteria:
  - New test file `httptap/redact_test.go` with `TestHeaderToStringWithRedact` subtests:
    `non_canonical_set_cookie_redacted` (`http.Header{"set-cookie": {"s=x"}}` → output
    lacks `s=x`), `mixed_case_authorization_redacted` (`"aUtHoRiZaTiOn"`),
    `padded_key_redacted` (`" Cookie "`), `non_redacted_key_kept_verbatim`
    (`"x-trace-id"` is logged with its original spelling). The first three fail on
    current code.
  - New subtest in `TestNewPayloadHandlerWithOptions`:
    `response_header_set_directly_in_map_is_redacted` — `next` does
    `w.Header()["set-cookie"] = []string{"session=" + uniqueToken()}`; the token is absent
    from the logger buffer. Fails on current code.
  - Existing `case_insensitive_match`, `default_set_cannot_be_removed`,
    `non-redacted_header_visible`, and `sensitive headers are redacted` pass unchanged.
  - Gate green.
- Pitfalls & edge cases: do not canonicalise the *logged* key (output for canonical keys
  must stay byte-identical); `WithRedactHeaders("")` must not redact the empty key in a
  way that changes behaviour (empty keys are already skipped); keep map iteration order
  semantics unchanged (none are guaranteed today).
- Complexity: Easy

### Task 6: Fix recover header semantics — snapshot, deletions, 1xx, trailers (C5, C6, C8)

## Risks

- **Behaviour changes visible to consumers:** two more headers and seven query
  parameters vanish from payload logs; a recover-wrapped handler that panics after
  `Flush` now re-panics with `http.ErrAbortHandler`. An outer recover middleware that does
  not special-case `ErrAbortHandler` will log it. Mitigation: CHANGELOG entries; the
  consumer fleet (owner memory `project_consumer_fleet`) should be checked for recover
  wrapping streaming routes before release.
- **Header-map identity:** Task 6 replaces the real header map's contents on commit. An
  outer middleware that holds a reference to the real map keeps a valid reference (the
  map is mutated in place, never reassigned).
- **Docs drift:** `AGENTS.md:74` and `README.md:75` enumerate the old four-header default
  set and do not mention query redaction; `doc.go`'s example assigns two results from
  `NewPayloadHandlerWithOptions`, which returns one. Docs are out of scope here; Task 8
  creates a backlog entry as an acceptance criterion (filename produced by
  `backlog-triage.sh --name`). The entry also covers the `README.md:75-76` advice against
  streaming routes, which Task 7 makes stale. It feeds the separate hygiene plan that
  rewrites `AGENTS.md`.
- **Concurrent edits:** lint plans (S1 moves `var _` assertions out of `rw.go`,
  `access.go`, `recover.go`; S2 removes the `loginjector` import alias) touch the same
  files. Rebase rather than redo; the renamed `tapWriter` assertion follows wherever S1
  moves the assertions.
- **Out of scope, noted for follow-up:**
  - Response and request header *values* can carry CR/LF set by the handler and are not
    escaped in the payload dump.
  - Credentials inside header *values* are not masked: `Referer` (the previous page's
    URL, which can carry OAuth `?code=` or `access_token`) and `Location` (OAuth
    redirects carrying `code`/`access_token`) are logged verbatim. Query redaction in this
    plan covers only the request's own query string. The Task 8 Security bullet states
    this gap; it does not claim header-value redaction.
  - The payload dump logs live response headers, not the headers frozen at
    `WriteHeader`.
  Raise one backlog entry each if the owner wants them tracked.

## Trade-offs

- Chose commit-on-`Flush` over a buffered no-op `Flush`: correct `net/http` semantics and
  working streaming, at the cost of losing 500 replacement after the first `Flush`.
- Chose `http.ErrAbortHandler` re-panic over silent return after commit: the client sees
  an aborted response rather than a truncated one that looks complete, at the cost of a
  panic reaching outer middleware.
- Chose masking (`name=[REDACTED]`) for query parameters over omitting them: keeps the
  request shape debuggable; headers keep omission for byte compatibility.
- Chose minimal control-character escaping over `URL.EscapedPath()`: byte-identical
  output for every normal path, at the cost of an ambiguity between a literal `%0A` and an
  escaped newline.
- Chose a single internal `beforeFlush` hook on a renamed unexported interface over
  per-wrapper flusher types: one mechanism for three wrappers and no change to the eight
  composites' advertised interfaces.
- Chose a small, unambiguous default query set over a broad one: avoids hiding
  non-secret parameters such as `page_token`-like names; broader coverage stays opt-in via
  `WithRedactQueryParams`.
