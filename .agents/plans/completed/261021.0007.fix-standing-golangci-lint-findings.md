# Task Breakdown

## Overview

GitHub issue #18. `.golangci.yml` was adopted in `fcd8659` with a `--new-from-rev` baseline
(`make lint-new`); the full tree still carries 379 standing findings, so `make lint` fails.
This plan clears them so `make lint` (golangci-lint over `./...` plus
`scripts/lint-checks.sh`) exits 0, without changing the public API of
`github.com/prorochestvo/loginjector` or its `httptap`/`levels` subpackages, and with one
documented, additive runtime delta (error wrapping in `TelegramHandler`, see Task 3).
Every finding group is classified below as auto-fixable, manual-mechanical, or judgment;
every judgment carries its decision, reasoning, and reversal path.

Baseline (golangci-lint 2.15.0, `CGO_ENABLED=0 golangci-lint run --max-issues-per-linter=0
--max-same-issues=0 ./...`): testifylint 107, paralleltest 52, gocritic 50, intrange 37,
noctx 37, revive 37, godot 12, tparallel 10, errorlint 8, staticcheck 8, perfsprint 6,
copyloopvar 6, funcorder 3, nakedret 2, gochecknoinits 1, govet 1, nilnesserr 1, unused 1.
Of these, 213 carry a linter-supplied suggested fix. `scripts/lint-checks.sh` is already
clean (exit 0).

## Assumptions

- Branch `chore/18-fix-lint-findings` is checked out; all work lands there and squash-merges
  into `main` as one commit (AGENTS.md release workflow).
- The module floor stays `go 1.22.2`. Verified on 2026-10-21 against the go1.22.2 toolchain
  source (`golang.org/toolchain@v0.0.1-go1.22.2`, `src/net/http/httptest/httptest.go`):
  - `httptest.NewRequestWithContext` does not exist (added in Go 1.23); using it would
    fail `go vet` (stdversion) under the 1.22.2 floor.
  - `httptest.NewRequest` has no `body == http.NoBody` special case, so passing
    `http.NoBody` yields `ContentLength == -1` on 1.22 versus `0` for `nil`. Rewriting the
    tests' `nil` bodies to `http.NoBody` would change the requests the tests construct on
    the floor toolchain.
- Every exact finding count in this plan and its acceptance criteria refers to the
  locally installed golangci-lint 2.15.0; version drift against the Makefile pin is out
  of scope. golangci-lint used for verification is the locally installed 2.15.0. The Makefile pins
  `GOLANGCI_VERSION := v2.12.2` only as an install hint; the two versions may disagree on
  findings (see Risks).
- "Production code" means every non-`_test.go` file, including
  `internal/synctest/synctest.go` (test scaffolding, but compiled as a normal package).
- Exported identifiers, signatures, error message bytes, and log output bytes are
  frozen. Unexported identifiers and declaration order may change.
- `nolintlint` is configured with `require-explanation`, `require-specific`,
  `allow-unused: false`: every `//nolint` names exactly the linter(s) it silences, carries
  a `// reason`, and must still be needed, or the run fails.
- A `//nolint:<linter>` comment placed on the line directly above a `func` declaration
  covers the whole function body, including its `t.Run` subtests.

### Needs judgment

**J1. noctx in tests (36 findings, all `httptest.NewRequest`)** — *suppress via config.*
The replacement `httptest.NewRequestWithContext` requires Go 1.23; the module floor is
1.22.2 and `go vet` would reject it. Add one narrow exclusion rule to `.golangci.yml`
(path `_test\.go`, linter `noctx`, text `httptest\.NewRequest must not be called`).
The production finding (`handler.go:67`) is not covered by the rule and is fixed (J4).
Reversal: when the `go` directive is raised to ≥ 1.23, delete the rule and migrate the
call sites to `httptest.NewRequestWithContext(t.Context()…)` (≥ 1.24) or
`context.Background()`.

**J2. gocritic httpNoBody in tests (33 findings)** — *suppress via config.*
On the 1.22.2 floor, `httptest.NewRequest(…, http.NoBody)` sets `ContentLength = -1`
whereas `nil` gives `0` (verified, see Assumptions); httptap logs and buffers bodies, so the
rewrite would change the inputs these tests feed the middleware. Add a narrow exclusion
(path `_test\.go`, linter `gocritic`, text `httpNoBody`). Production has no hits, so the
check stays fully active there. Reversal: when the floor reaches ≥ 1.23 (which special-cases
`http.NoBody`), delete the rule and run `--fix`.

**J3. errorlint (8, all production)**
- `handler.go:41,43,47,54,58,64` (`TelegramHandler`, multipart construction errors,
  `%s` with an `error`) — *fix: change to `%w`.* The rendered message is byte-identical
  (`%w` formats like `%v`). The only observable delta is additive: callers can now
  `errors.Is`/`errors.As` through to the underlying `mime/multipart` error. These errors
  come from writing into an in-memory `bytes.Buffer` and do not occur in practice. This is
  the house error contract (`stack-go:conventions`: wrap with `%w`). It is the one
  deliberate runtime delta in this plan and is recorded in `CHANGELOG.md` (Task 6).
  Owner decision (plan review round 1): accepted — additive, message bytes unchanged.
  Reversal: revert to `%s` and add `//nolint:errorlint // …` on each line.
- `handler.go:89` (`could not decode response: %v\n%s`) — *suppress.* `err` is nil when
  the branch is entered via `!response.Ok`; `%w` with a nil error renders `%!w(<nil>)`
  instead of `<nil>`, changing the message. Add
  `//nolint:errorlint // err may be nil when response.Ok is false; %w would render %!w(<nil>)`.
  Reversal: split the condition into two branches (message change, needs a CHANGELOG entry).
- `httptap/recover.go:63` (`pv == http.ErrAbortHandler`) — *suppress.* `pv` is a
  `recover()` value, not an error chain; identity comparison mirrors `net/http`'s own
  handling. `errors.Is` would also silently re-panic on a panic value that merely wraps
  `ErrAbortHandler`, a behaviour change. Add
  `//nolint:errorlint // recover value compared by identity, matching net/http's ErrAbortHandler handling`.

**J4. noctx in production (`handler.go:67`, `TelegramHandler`)** — *fix.* Replace
`http.NewRequest("POST", url, payload)` with
`http.NewRequestWithContext(context.Background(), http.MethodPost, url, payload)`.
`http.NewRequest` is itself defined as exactly this call, so behaviour is identical; the
handler is an `io.Writer` with no caller context, which `context.Background()` states
honestly. Timeout (20 s `http.Client.Timeout`), retry (none), and degradation (error
returned to the fan-out) are unchanged. Reversal: revert the line.

**J5. nilnesserr (`handler.go:406`, `FileByFormatHandler`)** — *fix.*
`err` is provably nil at that point, so `errors.Join(err, e)` equals `errors.Join(e)`.
Rewrite as `err = errors.Join(e)` — same `*errors.joinError` type and message as before
(rewriting to `err = e` would change the returned error's concrete type, so it is
rejected). Reversal: revert the line and add a nolint.

**J6. gochecknoinits (`error.go:445`)** — *fix.* The `init` only sets
`runtimeDetails.once = &sync.Once{}`. Move that into the variable's initializer
(`var runtimeDetails = struct{ once *sync.Once; value string }{once: &sync.Once{}}`).
Package-level variable initialization completes before any `init` and before any caller,
so the observable behaviour is identical, and `resetRuntimeCacheForTest` in
`error_test.go` keeps working because the field remains a pointer. Reversal: restore the
`init`.

**J7. gocritic ptrToRefParam (`closers.go:53`, exported `CloseOrJoin(errp *error, c io.Closer)`)**
— *suppress.* Changing the parameter would break the public API, and the pointer is the
contract (the deferred call writes the joined error through it). Add
`//nolint:gocritic // errp is written through by design; part of the public CloseOrJoin API`.

**J8. paramTypeCombine (`handler.go:753`, unexported `parseRotationIndex`)** — *fix.*
`(index int, gz, ok bool)`; unexported, signature-identical.

**J9. testifylint go-require (18)**
- `handler_test.go:369` (`require` inside a spawned goroutine in
  `TestFileByFormatHandlerForRaceCondition`) — *fix: real defect.* `FailNow` from a
  non-test goroutine does not stop the test. Use `assert.*` inside the goroutine.
- 17 in `httptap/{access,recover,rw}_test.go` (`require` inside HTTP handler closures) —
  *fix.* The handlers run synchronously on the test goroutine (no `httptest.NewServer` in
  the package), so today they work, but under the recover middleware a `FailNow`
  (`runtime.Goexit`) passes through a deferred `recover()` path, which is fragile. Switch to
  `assert.*`. Where a later line in the same handler depends on the assertion (type
  assertion result, non-nil value), guard with `if !assert.X(…) { return }` so a failure
  cannot become a nil dereference that the recover middleware would swallow as a 500.
  Concrete pattern for the type-assertion sites (`httptap/recover_test.go:179,209,330,354`,
  `httptap/rw_test.go:278`, `httptap/access_test.go:208,236`):
  ```go
  hj, ok := w.(http.Hijacker)
  if !assert.True(t, ok, "ResponseWriter must implement http.Hijacker") {
  	return
  }
  conn, _, err := hj.Hijack()
  if !assert.NoError(t, err) {
  	return
  }
  ```
  `require` calls outside the handler closure, on the test goroutine (e.g.
  `httptap/recover_test.go:189,337`), stay `require`.

**J11. testifylint encoded-compare (4, `httptap/recover_test.go:113,140,244,319`)** —
*suppress.* These assertions check the recover middleware's exact 500 response body with
`require.Equal`/`assert.Equal`. `JSONEq` ignores whitespace, key order, and the trailing
newline, so the rewrite would weaken a byte-exact public contract. Keep `Equal` and add
`//nolint:testifylint // response body bytes are the public contract` on each line.
Reversal: accept the `JSONEq` rewrite if the body is ever declared semantically (not
byte-wise) stable.

**J12. `httptap/redact.go` `headerToStringWithRedact` (gocritic ruleguard concat-in-loop
at :25, perfsprint concat-loop at :35)** — *fix manually.* Replace `res := ""` / `res +=`
with a `strings.Builder` that writes `key`, `": "`, `val`, `"\n"` in that order, so each
line stays byte-identical to `key + ": " + val + "\n"`. Both findings clear with this one
change. Production file; output unchanged (map iteration order is already random, and the
existing redact/payload tests assert per-line content).

**J10. paralleltest (52) and tparallel (10)** — *per-test decision.*
Rule: a test stays serial (with a function-level `//nolint:paralleltest` or
`//nolint:paralleltest,tparallel` and a reason) when it or any of its subtests mutates
process-global state or depends on running alone; otherwise it gets `t.Parallel()` at the
top level and in every subtest. Serial top-level tests finish before any parallel top-level
test resumes, which is exactly the isolation the global-state tests rely on — making them
parallel is unsafe.

Stay serial (nolint with the stated reason):

| Test | Reason |
|---|---|
| `error_test.go` `TestSetRuntimeDetailsProvider`, `TestRuntimeDetailsFrozen` | mutate the process-wide runtime-details cache and provider (`resetRuntimeCacheForTest`) |
| `filelogger_test.go` `TestNewFileLogger` | subtests swap the std `log` output and write to the shared `os.TempDir()/logs` directory (paralleltest + tparallel) |
| `handler_test.go` `TestPrintHandler` | `captureStdout` redirects process-global `os.Stdout` |
| `logger_test.go` `TestNewLogger` | `captureStdout` redirects process-global `os.Stdout` |
| `logger_test.go` `TestLogger_Write` | calls `log.SetOutput` on the std logger |
| `rotating_newopts_test.go` `TestWithFileMode` | sets the process umask (`syscall.Umask`) |
| `internal/stacktrace_test.go` `TestStackTrace` subtest at line 31 | documented: both stack captures must be compared on the same goroutine; kept serial as written |
| `httptap/payload_test.go` `TestSummaryWriter` | documented: subtests share `os.Stdout` as the default summary destination |

Additionally, `TestLogger_Write` never restores the std logger output; add
`prev := log.Writer(); t.Cleanup(func() { log.SetOutput(prev) })` so later parallel tests
do not log into its buffer (test-only).

Make parallel (top level plus every flagged subtest):

| File | Tests |
|---|---|
| `error_test.go` | `TestHttpError`, `TestFullTrace`, `TestNewTraceError` (top level only) |
| `logger_test.go` | `TestLogger_SetMinLevel`, `TestLogger_Hook` (+4 subtests), `TestLogger_HookBelowMinimum`, `TestLogger_Unhook`, `TestLogger_WriteLog`, `TestLogger_PrintAndPanic`, `TestLogger_WriterAs` |
| `handler_test.go` | `TestTelegramHandler` (+subtest), `TestRotatingFileHandler` (+2 subtests), `TestRotatingFileHandlerForRaceCondition`, `TestFileByFormatHandler`, `TestFileByFormatHandlerV2`, `TestFileByFormatHandlerForRaceCondition`, `TestVerifyFiles`, `TestRotatingFileHandler_FreshStartForRaceCondition` |
| `filelogger_test.go` | `TestNewFileLogger_RotationOptions` (top level) |
| `rotating_newopts_test.go` | `TestWithMaxAgeDays` (top level) |
| `rotating_options_test.go` | `TestRotatingFileHandler_StableCurrentName`, `TestRotatingFileHandler_MaxAge`, `TestPruneRotation`, `TestRotatingFileHandler_Compress` (top level), `TestRotatingFileHandler_OptionsForRaceCondition` |
| `httptap/payload_test.go` | `body_cap_race_condition` subtest (its comment already describes it as parallel and it sets `WithSummaryWriter(io.Discard)`) |

## Trade-offs

- Chose config-level, text-scoped exclusions over 69 per-line `//nolint` comments for J1/J2
  because both have a single cause (the Go floor) and a single removal condition; per-line
  comments would scatter the same reason across five files.
- Chose `%w` over suppression for the six `TelegramHandler` sites because the message bytes
  are unchanged, the wrapped errors cannot occur in practice, and suppression would
  contradict the error contract the linter enforces. Alternative (strict zero-delta):
  keep `%s` and nolint each line.
- Chose to keep documented serial tests serial with nolint over refactoring them to avoid
  globals (e.g. injecting `os.Stdout` or the umask), because that refactor would touch
  production seams and exceeds a lint-cleanup scope.
- Chose `errors.Join(e)` over `err = e` at `handler.go:406` to keep the returned concrete
  error type identical.
- Chose to delete the unused unexported `newInterceptor` rather than suppress, because it
  has no callers and is not part of the public API.
