# Task Breakdown

## Overview

The 2026-10-22 project review (consolidated findings on `main` @ 434ed68, plus commit
e892262 which already scoped zero-option pruning to the handler's own prefix via
`verifyRotationFiles`) left six defects in the file handlers (`handler.go`:
`RotatingFileHandler`, `FileByFormatHandler`, the rotation/prune internals; `filelogger.go`:
`NewFileLogger`). Two of them destroy data:

- **C1** — `globRotation` builds `filepath.Glob(filepath.Join(folder, "*.log"))`, so
  metacharacters in `folder` are interpreted: a handler on `logs/app[1]` resumes from,
  prunes, and fresh-start-deletes files in `logs/app1`. A malformed folder (`logs/app[`)
  makes every scan fail with `filepath.ErrBadPattern`. `removeCompressTemps` has the same
  flaw.
- **C2** — `pruneRotation` keeps `maxFiles-1` backups on the assumption that the live file
  exists. After a rotation the replacement live file does not exist yet (it is created
  lazily by the next write), so with `WithMaxFiles(1)` on any opt-in path
  (`WithCompress`, `WithStableCurrentName`, `WithMaxAge`) the backup holding the triggering
  write's data is deleted immediately: the write returns success and its data is gone.

The remaining four violate contracts:

- **#3** — `NewFileLogger` runs `os.Chmod(folder, 0o750)` on a pre-existing folder (".",
  `/var/log/app`), silently changing permissions the caller owns, or failing with `EPERM`
  when the process is not the owner.
- **#8** — both file handlers return `len(bytes.TrimSpace(msg))+1` instead of `len(p)`:
  `n < len(p)` with a nil error when the message has surrounding whitespace, `n > len(p)`
  for an empty message. Both violate the `io.Writer` contract.
- **#13** — `WithMaxFiles(0)` / a negative value (and `FileByFormatHandler`'s
  `maxFilesInFolder <= 0`) deletes every file including the one just written;
  `FileByFormatHandler` joins the generator's output into a path without checking for
  separators, so a generated `../x` writes outside `folder`.
- **#9** — open/write/write/close per message. This plan coalesces the two writes into one
  (part of Task 4) and **defers** keeping the descriptor open between writes; see
  Trade-offs and the Deferred section.

Out of scope: the logger core, `httptap`, `TelegramHandler`, human docs (README,
AGENTS.md). Godoc of the touched functions is updated where behaviour changes.

## Assumptions

- `main` is at e892262 or later; `verifyRotationFiles` (prefix-scoped zero-option prune) is
  present and is built upon, not replaced.
- Go floor stays 1.22.2 (`go.mod`); stdlib + testify only. `os.ReadDir`, `filepath.IsLocal`
  and integer `range` are available.
- Single-writer invariant per `(folder, prefix)` stays as documented; no cross-process
  locking is added.
- Windows is not a test target, but path handling stays portable (`filepath` only, no
  hard-coded `/`); permission-bit assertions skip on `runtime.GOOS == "windows"`.
- The project is on the 1.0.x line, where fixes ship as a patch release
  (see `[Unreleased]` in `CHANGELOG.md`). Nothing in this plan removes or renames an
  exported identifier.
- On-disk names and line format stay byte-identical. The only on-disk behaviour changes
  are the ones a finding requires, each recorded in Trade-offs with its reversal path.

## Tasks

### Task 1: Replace glob-based rotation scans with directory listing (C1)

- Description:
  - In `handler.go`, replace `globRotation(folder string, includeGz bool)` with an
    unexported `listRotation(folder string, suffixes ...string) ([]string, error)` that
    calls `os.ReadDir(dirOrDot(folder))`, keeps entries with `!e.IsDir()` whose name ends
    with one of `suffixes` (symlinks stay listed, as with `Glob`), and returns
    `filepath.Join(folder, name)` for each. Order is one name-sorted pass, so `.log` and
    `.log.gz` names interleave, unlike `Glob`'s per-pattern concatenation; no caller
    depends on the order (the prune paths sort or group by index).
  - `folder == ""` must list `"."` (today `filepath.Join("", "*.log")` globs the working
    directory; `os.ReadDir("")` fails). Returned paths keep `filepath.Join(folder, name)`
    so they are identical to what `Glob` returned.
  - A missing folder (`errors.Is(err, fs.ErrNotExist)`) returns `(nil, nil)`, preserving
    the documented "missing file or folder is a no-op" behaviour of `WithFreshStart` and
    resume. Any other `ReadDir` error is returned (see Trade-offs: previously swallowed).
  - Call sites: `resumeRotation`, `resetRotation`, `verifyFiles`, `verifyRotationFiles`,
    `listBackups`, `reconcileCompressed` pass `"."+defaultFileExtension` and, where
    `includeGz`/`cfg.compress` was true, also `"."+defaultFileExtension+"."+gzipExtension`.
    `removeCompressTemps` uses `listRotation(folder, ".log.gz.tmp")` instead of its own
    `filepath.Glob`. No `filepath.Glob` remains in `handler.go` production code.
  - Update the comments that cite "glob literal patterns" (`resumeRotation`,
    `resetRotation`, `removeCompressTemps`, the old `globRotation` doc) to describe the
    listing; the prefix filter via `parseRotationIndex` is unchanged.
- Acceptance Criteria:
  - New subtests (fail on current code):
    - `TestRotatingFileHandler` / "folder with glob metacharacters is literal": under
      `base := t.TempDir()` create `base/app[1]` and a decoy `base/app1` holding
      `app.00000001.log`..`app.00000003.log`. `RotatingFileHandler(base/app[1], "app",
      WithMaxFileSize(4), WithMaxFiles(2))`, six writes of `"0123456789"`, no error; all
      three decoys exist with their original bytes; `base/app[1]` holds exactly 2 own files
      and resume started at index 1 (first file is `app.00000001.log`).
    - Same layout with `WithFreshStart()`: decoys survive construction and the first write.
    - Same layout with `WithCompress()` + `WithMaxFiles(2)`: decoy `.log`, `.log.gz`, and
      `.log.gz.tmp` files in `base/app1` survive.
    - "malformed glob folder": folder `base/app[`; three rotating writes return nil error
      (current code returns `syntax error in pattern` from the prune).
    - `TestFileByFormatHandler` / "folder with glob metacharacters is literal": folder
      `base/f[1]`, two decoys `base/f1/old1.log` and `base/f1/old2.log`,
      `maxFilesInFolder` 1, two writes with different generated names; both decoys
      survive and `base/f[1]` ends with exactly 1 file. (A single decoy would pass on
      current code: with limit 1 nothing is pruned.)
    - "folder entry that is a directory is ignored": in `dir` create a sub-directory
      named `app.00000009.log`; `RotatingFileHandler(dir, "app", WithMaxFileSize(4),
      WithMaxFiles(2))`, three writes of `"0123456789"`; no write error, the directory
      still exists, and exactly 2 own regular files remain. (Today the directory is the
      resume target, so the first open fails.)
  - Existing tests, including `TestVerifyFiles`, `TestPruneRotation`,
    `TestRotatingFileHandler_FreshStartForRaceCondition`,
    `TestRotatingFileHandlerForRaceCondition`, stay green unchanged.
  - `grep -n 'filepath.Glob' handler.go` returns nothing.
- Pitfalls & edge cases:
  - Use `[` for the metacharacter folder; `*` and `?` are invalid in Windows file names.
  - `DirEntry.IsDir()` does not follow symlinks; a symlink named like a backup is still
    listed (same as `Glob`). Do not add `os.Stat` per entry here; `listBackups` already
    stats what it groups.
  - `verifyFiles` and `verifyRotationFiles` still `sort.Strings` the result; keep that,
    do not rely on `ReadDir` order implicitly.
  - `verifyRotationFiles` reuses the backing array (`own := files[:0]`); keep it safe
    since `listRotation` returns a fresh slice.
- Complexity: Medium

### Task 2: Clamp the file-count bound and validate generated names (#13)

- Description:
  - `RotatingFileHandler`: after applying options, `if cfg.maxFiles < 1 { cfg.maxFiles = 1 }`.
    This covers `NewFileLogger` (`WithMaxFilesInFolder` forwards to `WithMaxFiles`).
  - `FileByFormatHandler`: at construction, `if maxFilesInFolder < 1 { maxFilesInFolder = 1 }`.
  - `FileByFormatHandler`: per write, before `os.OpenFile`, reject a generated name that
    is not a plain file name: `name == ""`, `name == "."`, `name == ".."`, or
    `filepath.Base(name) != name`. Return `0, fmt.Errorf("loginjector: generated file
    name %q must be a plain file name", name)`; create nothing and do not prune.
  - `FileByFormatHandler` never prunes the file it just wrote: change
    `verifyFiles(folder string, limit int)` to `verifyFiles(folder string, limit int,
    current string)`. When `current` is non-empty it is excluded from the candidates and
    counts as the +1, so at most `limit-1` other `*.log` files survive (oldest by name
    removed). `current == ""` keeps today's semantics (keep `limit`); `TestVerifyFiles`
    passes `""` and stays green. The handler passes `filepath.Join(folder, fileName)`.
  - Godoc: `WithMaxFiles`, `WithMaxFilesInFolder`, and `FileByFormatHandler` state that
    values below 1 are treated as 1; `FileByFormatHandler` states the name rule and that
    the file just written is never pruned.
- Acceptance Criteria:
  - New subtests (fail on current code):
    - `RotatingFileHandler(dir, "app", WithMaxFileSize(3), WithMaxFiles(0))`: write
      `"abcd"` (rotates), assert `app.00000001.log` still exists with `"abcd\n"`; repeat
      with `WithMaxFiles(-5)`.
    - `FileByFormatHandler(dir, 0, gen)`: one write; the written file exists afterwards.
    - Non-time-sorted names: `FileByFormatHandler(dir, 1, gen)` with `gen` yielding `"b"`
      then `"a"`; after the second write `a.log` exists (holding the second line) and
      `b.log` is gone. Today the lexical prune deletes `a.log`, the file just written.
    - `FileByFormatHandler` with generators returning `"../escape"`, `"a/b"`, `""`, `"."`,
      `".."`: each `Write` returns `n == 0` and a non-nil error; no file is created inside
      `dir` or its parent (assert `filepath.Join(filepath.Dir(dir), "escape.log")` does not
      exist).
  - A valid generated name (`"2026-10-22"`) still writes `2026-10-22.log` byte-identically.
- Pitfalls & edge cases:
  - `".."` with the appended extension becomes `"...log"`, which does not escape; it is
    rejected anyway for clarity. Do not use `filepath.IsLocal` alone: `"a/b"` is local
    but lands in a sub-directory.
  - On Unix a backslash is a legal file-name byte and `filepath.Base` does not treat it as
    a separator; that is correct portable behaviour, do not special-case it.
  - Exclusion is by full path equality against the listing output; both are built with
    `filepath.Join(folder, name)`, so they compare equal byte for byte.
  - Other files are still pruned oldest-by-name; a generator whose names do not sort
    chronologically keeps the current file but may prune a newer-in-time older-by-name
    file. That remains the documented whole-folder contract.
  - The clamp must run after all options, so `WithMaxFiles(0)` followed by
    `WithMaxFiles(3)` still yields 3.
- Complexity: Easy

### Task 3: Never prune the triggering write's only copy (C2)

- Description:
  - `rotate()` knows which index it just rotated out; pass it to
    `pruneRotation(folder, prefix, cfg, liveBase, protectIdx, now)`:
    - indexed mode: `protectIdx = oldIndex` (plain or compressed);
    - stable mode: the backup index used by a successful `os.Rename` of `prefix.log`
      (the value of `index` before the `index++`); `0` when `prefix.log` was absent or the
      rename failed (the data is still in `prefix.log`).
    - `0` means "nothing protected"; rotation indices start at 1, so it never collides.
  - In `pruneRotation`, the protected group (if listed) is removed from the candidate list
    before both phases:
    - age phase: never removed (it is the data just rotated out; `WithMaxAge(14)` — 14 ns
      — would otherwise delete it);
    - count phase: total retained backups = `cfg.maxFiles - 1`, raised to 1 when a
      protected group exists; the protected group occupies one of those slots, so at most
      `keep - 1` other backups survive, oldest removed first.
  - No `os.Stat` of the live file: protection is keyed on the index, not on whether the
    live file exists. This also covers rotating into a pre-existing higher-index file
    (live present), where a live-existence check would still delete `oldIndex`.
  - Count results change only for `maxFiles == 1` (after Task 2's clamp, also
    `0`/negative): the steady state becomes "live + 1 backup", matching what the
    zero-option `verifyRotationFiles` path produces with `limit == 1`. The age-phase
    protection changes `maxFiles >= 2` too: a short `WithMaxAge` no longer ages out the
    backup produced by the same rotation; it ages out on the next rotation.
  - Update the `pruneRotation` and `WithMaxFiles` godoc: the bound is enforced at
    rotation; the backup just rotated out survives until a newer live file replaces it.
- Acceptance Criteria:
  - New subtests in `TestRotatingFileHandler_Compress`,
    `TestRotatingFileHandler_StableCurrentName`, `TestRotatingFileHandler_MaxAge`
    (fail on current code):
    - `WithMaxFiles(1), WithMaxFileSize(3), WithCompress()`: write `"abcd"`;
      `app.00000001.log.gz` exists and decompresses to `"abcd\n"`.
    - `WithMaxFiles(1), WithMaxFileSize(3), WithStableCurrentName()`: write `"abcd"`;
      `access.00000001.log` holds `"abcd\n"`.
    - `WithMaxFiles(1), WithMaxFileSize(3), WithMaxAge(time.Hour)`: write `"abcd"`;
      `app.00000001.log` holds `"abcd\n"`.
    - Steady state, `WithMaxFiles(1)` + `WithCompress()`: writes `"abcd"`, `"efgh"`,
      `"ijkl"` (each rotates); exactly one `.gz` remains and it holds `"ijkl\n"`.
    - `WithMaxFiles(0)` + `WithMaxFileSize(3)` + `WithCompress()` (clamped by Task 2):
      write `"abcd"`; `app.00000001.log.gz` decompresses to `"abcd\n"`.
    - `WithMaxFiles(1), WithMaxFileSize(3), WithMaxAge(time.Nanosecond)` + compress: the
      newest backup survives the rotation that produced it.
    - `WithMaxFiles(3), WithMaxFileSize(3), WithMaxAge(time.Nanosecond)`: after one
      rotating write `app.00000001.log` survives; after a second rotating write index 1 is
      aged out and index 2 survives.
    - Rotating into a pre-existing higher-index file: construct
      `RotatingFileHandler(dir, "app", WithMaxFiles(1), WithMaxFileSize(3), WithCompress())`
      on an empty `dir`, then plant `app.00000002.log` holding `"planted\n"`, write
      `"abcd"`; `app.00000001.log.gz` decompresses to `"abcd\n"` and `app.00000002.log`
      still starts with `"planted\n"`.
  - New `TestPruneRotation` cases: `maxFiles: 1`, backups 1..3, `protectIdx: 2` → only 2
    survives; same with `protectIdx: 0` → none survive (unchanged); `maxFiles: 3`,
    backups 1..5, `protectIdx: 1` → 1 and 5 survive; age case with every backup over-age
    and `protectIdx: 3` → only 3 survives.
  - Existing `TestPruneRotation` cases gain the `protectIdx` argument as `0`; their
    assertions are unchanged and stay green. If any case fails, the implementer stops and
    reports instead of editing the assertion.
  - Existing "small maxFiles over many rotations keeps prefix.log" (`<= 2` files) and
    "prune counts .log and .log.gz" (`<= 2` gz) stay green.
  - `TestRotatingFileHandler_OptionsForRaceCondition` gains a second handler run with
    `WithMaxFiles(1)` and `WithCompress()` under 16 concurrent writes, asserting no error
    and `-race` cleanliness only (which message survives is nondeterministic).
- Pitfalls & edge cases:
  - Indexed mode: `rotate` may move into a pre-existing higher-index file; `oldIndex` is
    still protected, which is the case a live-existence check gets wrong.
  - Stable mode: the `backupExists` loop may advance `index` past collisions before the
    rename; protect the index actually renamed into, not the pre-loop value.
  - The zero-option `verifyRotationFiles` has the same theoretical edge only when an
    external process plants a higher-index file; it is not changed here (it keeps the
    newest `limit` existing files, which covers every handler-produced layout).
  - A `.log`/`.log.gz` pair for the protected index is protected as a unit (the group is
    the unit everywhere in `pruneRotation`).
- Complexity: Medium

### Task 4: Honour the io.Writer contract and write each line once (#8, part of #9)

- Description:
  - Add an unexported helper at the bottom of `handler.go`:
    `appendLine(path string, perm os.FileMode, buf *[]byte, msg []byte) (written int, complete bool, err error)`.
    It builds `trimmed + '\n'` into the reused `*buf` (`(*buf)[:0]`, append), opens with
    `os.O_WRONLY|os.O_CREATE|os.O_APPEND`, performs a single `f.Write`, closes explicitly,
    and returns bytes actually written, `complete` (the write call returned the full
    buffer length with a nil error), and the joined open/write/close error. After the
    write, if `cap(*buf) > 64<<10` reset `*buf = nil` so one large message does not pin
    memory. The buffer is safe to reuse because both handlers run under their `writer`
    mutex.
  - `RotatingFileHandler`: replace the open/write/write/close block with `appendLine`;
    `fileSize += uint64(written)`; rotate exactly as today. Return value:
    - `!complete` (open failure, write error, short write) → `0, errors.Join(seedErr, ioErr, rotateErr)`;
    - `complete` → `len(msg), errors.Join(seedErr, closeErr, rotateErr)`. A Close error,
      seed error, or rotation error after a completed write is reported with
      `n == len(p)`, which the contract allows, so callers do not retry and duplicate the
      line.
  - `FileByFormatHandler`: same helper and the same return rule (close or prune error
    with `n == len(p)`).
  - Godoc of both handlers: "Write returns len(p) when the line was written in full, 0
    with a non-nil error when it was not; a close, rotation or prune error after a full
    write is returned with n == len(p)."
  - On-disk bytes are unchanged: still `bytes.TrimSpace(msg)` followed by one `'\n'`.
- Acceptance Criteria:
  - New subtests (fail on current code):
    - `RotatingFileHandler.Write([]byte("  hi  \n"))` returns `n == 7`, nil error; file
      holds `"hi\n"`.
    - `RotatingFileHandler.Write([]byte{})` returns `n == 0`, nil error; file holds `"\n"`
      (current code returns 1).
    - The same two cases for `FileByFormatHandler`.
    - Rotation error after a persisted write: `RotatingFileHandler(dir, "app",
      WithMaxFileSize(3), WithCompress())`, then plant `app.00000001.log.gz.tmp` (after
      construction, so reconcile does not remove it), write `"abcd"`: error is non-nil
      (O_EXCL on the temp fails) and `n == 4`.
    - Open failure (folder is a regular file): `n == 0`, non-nil error (passes today;
      keeps the error path pinned).
    - The Close-error branch is not reproducible portably in a test; it is covered by
      review of the return rule.
  - `go test -run '^$' -bench BenchmarkRotatingFileHandler_Write -benchmem` reports
    allocs/op no higher than on `main` (record both numbers in the commit body).
  - All existing content assertions in `TestRotatingFileHandler`, `TestFileByFormatHandler`,
    `TestFileByFormatHandlerV2`, `TestNewFileLogger`, and the option tests stay green
    unchanged.
- Pitfalls & edge cases:
  - Never `append(trimmed, '\n')` directly: `trimmed` aliases the caller's `p`, and
    appending can overwrite the caller's bytes when `cap(p) > len(trimmed)`.
  - `fileSize` must count bytes actually written even on a short write, so rotation
    accounting stays correct after a partial write.
  - `TimestampedHandler` wraps the rotating handler in `NewFileLogger` and returns its own
    `len(msg)`; no change needed there.
  - A single `O_APPEND` write per line also stops two lines from different processes
    interleaving between the payload and its newline; mention it in the CHANGELOG only as
    a side effect, not as a supported multi-process guarantee.
- Complexity: Easy

### Task 5: Chmod only folders NewFileLogger created (#3)

- Description:
  - In `NewFileLogger` (`filelogger.go`), replace `os.MkdirAll(folder, 0o750)` with
    `os.MkdirAll(filepath.Dir(folder), 0o750)` followed by `os.Mkdir(folder, 0o750)`:
    - `Mkdir` returned nil → this call created the leaf → `os.Chmod(folder, 0o750)`;
    - `errors.Is(err, fs.ErrExist)` → pre-existing; `os.Stat` it and return the existing
      "create log folder" error when it is not a directory (keeps today's
      construction-time failure, which `MkdirAll` reported as `ENOTDIR`); no chmod;
    - any other error → returned as today.
    The create decision comes from `Mkdir`'s own result, so there is no Stat/Mkdir race.
  - The temp-fallback folder (`filepath.Join(os.TempDir(), "logs")`) is always chmodded
    to 0750, created or not, because its godoc presents the chmod as the defence against a
    permissive shared temp directory.
  - A pre-existing caller-supplied folder keeps its permissions.
  - Godoc: `NewFileLogger` states that a folder it creates is set to 0750 and a
    pre-existing folder's permissions are left unchanged; `WithTempDirFallback` keeps its
    chmod note.
- Acceptance Criteria:
  - New subtests in `TestNewFileLogger` (fail on current code), skipped on Windows:
    - pre-existing folder: `os.Mkdir(dir/"pre", 0o700)` then `os.Chmod(…, 0o755)`;
      `NewFileLogger(dir/"pre", …)` succeeds and the folder mode is still `0o755`.
    - created folder: `NewFileLogger(dir/"a/b", …)` → `b` is exactly `0o750` (passes
      today; pins the kept behaviour).
    - folder path that is an existing regular file: `NewFileLogger` returns a non-nil
      error (passes today; pins the ENOTDIR replacement).
  - Umask: a serial top-level `TestNewFileLogger_UnderRestrictiveUmask` in a new
    `filelogger_unix_test.go` (`//go:build unix`, counterpart of `filelogger.go`) sets
    `syscall.Umask(0o077)`, restores the previous mask with `t.Cleanup`, and asserts a
    created folder is exactly `0o750`. It must not call `t.Parallel`: the umask is
    process-global, and a serial top-level test runs before any parallel top-level test
    resumes. Record the reason in a `//nolint:paralleltest` comment.
  - The existing serial "temp fallback resolves under os.TempDir/logs" subtest stays
    green and additionally asserts the fallback folder is `0o750` after construction.
  - No production change outside `NewFileLogger` and its option godoc.
- Pitfalls & edge cases:
  - Umask: `MkdirAll` applies the umask; the explicit chmod on a created leaf is what
    makes it exactly 0750 — keep it. Intermediate parents created by `MkdirAll` are not
    chmodded (unchanged).
  - `filepath.Dir` of a relative single-segment folder is `"."`; `MkdirAll(".")` is a
    no-op. `folder` with a trailing separator: `filepath.Dir("logs/")` is `"logs"`, so
    `MkdirAll` creates the leaf and `Mkdir` reports `ErrExist`; clean the path with
    `filepath.Clean` first so the leaf is detected as created.
  - `Mkdir` returns `ErrExist` for an existing file as well as a directory, hence the
    `IsDir` check.
  - The temp-fallback subtest touches the shared `os.TempDir()/logs`; it stays serial
    with its existing `nolint` reason.
- Complexity: Easy

### Task 6: CHANGELOG [Unreleased] entries

- Description: read `CHANGELOG.md` first (an `[Unreleased]` section already exists with
  `### Changed` and `### Fixed`). Append to `### Fixed`, one bullet per finding, in plain
  factual wording, plus the `### Changed` bullets listed after them:
  - C1: rotation scans no longer interpret glob metacharacters in the folder path; a
    folder such as `logs/app[1]` no longer resumes from, prunes, or fresh-start-deletes
    files in `logs/app1`, and `logs/app[` no longer fails every rotation. Directory
    listing errors other than a missing folder are now returned instead of ignored.
  - C2: with `WithMaxFiles(1)` and `WithCompress`, `WithStableCurrentName`, or
    `WithMaxAge`, the backup holding the rotation-triggering write is no longer deleted
    and is no longer deleted when the rotation moves into a pre-existing higher-index
    file.
  - #13: `FileByFormatHandler` rejects generated names that are empty, `.`, `..`, or
    contain a path separator, and never prunes the file it has just written.
  - #8: `RotatingFileHandler` and `FileByFormatHandler` return `len(p)` after a full write
    and 0 on a failed write, per the `io.Writer` contract (previously
    `len(TrimSpace(p))+1`); each line is written with a single write call.
  - #3: `NewFileLogger` no longer changes permissions of a pre-existing folder; it sets
    0750 only on a folder it creates and on the temp-fallback folder.
  `### Changed`:
  - `WithMaxFiles`, `WithMaxFilesInFolder`, and `FileByFormatHandler`'s
    `maxFilesInFolder` treat values below 1 as 1 instead of deleting every file.
  - The file handlers report a close, rotation, or prune error that follows a full write
    with `n == len(p)` and the non-nil error.
  - With `WithMaxAge`, the backup produced by a rotation is no longer aged out by that
    same rotation; it becomes eligible on the next rotation.
  Each task's commit may add its own bullet instead; this task verifies the set is
  complete and consistent. No version header is promoted (release is a separate step).

  Reasons are in Trade-offs. The entry should require a benchmark showing the gain on the
  target filesystems before any design, and an opt-in shape (e.g. a new
  `RotatingFileOption`) that leaves the default path-following behaviour intact.

## Risks

- **Listing errors now surface** (Task 1): `filepath.Glob` swallowed `EACCES` and other
  I/O errors and returned an empty match set, silently disabling retention. A folder that
  is writable but not readable now reports an error on the first write and on every
  rotation. This is intended (retention that silently stops is worse), but a consumer
  ignoring `Write` errors sees no difference and one checking them sees new errors.
- **Permission change visibility** (Task 5): a deployment that relied on `NewFileLogger`
  tightening an existing folder to 0750 loses that. The godoc and CHANGELOG state it.
- **Empty generated name rejected** (Task 2): a generator that returned `""` previously
  wrote a hidden `.log`; it now gets an error per write. Such a generator is a bug, but
  it is a behaviour change.
- **Transient file count** (Task 3): with `maxFiles == 1` on opt-in paths, two files
  (live + newest backup) exist between rotations instead of the current
  delete-immediately behaviour. Matches the zero-option path; documented.
- **Age retention lags one rotation** (Task 3): with a short `WithMaxAge`, one backup
  older than the cutoff can exist until the next rotation. Recorded under `### Changed`.
- **Fragile area**: `rotate()` mutates `index`/`fileName`/`fileSize` captured by the
  closure; Tasks 3–4 must not move that state or reorder close-before-rotate (stable-name
  rename and gzip need the descriptor closed).

## Trade-offs

- **C1: `os.ReadDir` + suffix match over `filepath.Glob` with escaped folder.** Escaping
  metacharacters is platform-specific (no escaping on Windows) and easy to get wrong;
  listing the directory removes pattern semantics entirely. Cost: listing errors are no
  longer swallowed (see Risks). Reversal: restore `globRotation`.
- **C2: protect the index just rotated out (passed from `rotate()`), over a live-file
  existence check, rotating before the write (lumberjack style), or eagerly creating the
  new live file.** The existence check fails when rotation moves into a pre-existing
  higher-index file (round-1 review). Rotate-before-write
  moves the triggering line into the next file and changes which file each line lands in
  (existing tests such as "appends and rotates" pin today's layout); eager creation alone
  still deletes the triggering data when `maxFiles == 1`. The chosen rule changes count
  results only for `maxFiles == 1` (aligning it with the zero-option path) and delays age
  pruning of the newest backup by one rotation. Reversal: drop the `protectIdx` parameter
  and pass nothing protected.
- **#13: clamp to 1, over treating `<= 0` as unlimited or as the default 7.** The caller
  asked for the tightest bound; "unlimited" would turn a misconfiguration into unbounded
  disk growth, and silently substituting 7 ignores the request. Reversal: change the
  clamp in the two constructors.
- **#13: reject unsafe generated names per write with an error, over sanitising them.**
  Sanitising (`filepath.Base`) would write to a name the caller did not ask for. Reversal:
  remove the check.
- **#8: `n == len(p)` when the write completed even if close, rotation or prune then
  fails, over `n == 0` on any error.** The bytes reached the file; reporting 0 would
  invite a retry that duplicates the line. A Close error can in rare cases (NFS) mean the
  data did not persist; that is accepted, the error is still returned. Reversal: return 0
  whenever `err != nil`.
- **#9: coalesce to one write now, defer the persistent descriptor.** Keeping the file
  open changes behaviour under external log management: after `logrotate` renames the
  file, writes continue into the renamed file; after an external `rm`, writes go to an
  unlinked inode and are lost silently; after `copytruncate`, the size counter is wrong.
  The handlers have no `Close` in their API, so a cached descriptor would leak for the
  process lifetime (and on Windows would block the stable-name rename and test cleanup).
  Adding `io.Closer` or reopen-on-stat logic is new API and design work without a
  measured need. The coalesced write removes one syscall per line and is byte-identical
  on disk. Reversal: split the write back into two calls.
- **#8/#9: a reused per-handler buffer, over a fresh allocation per write.** Keeps the
  options-off hot path allocation-neutral (the benchmark's stated guard); the 64 KiB cap
  bounds retained memory. Reversal: allocate per call.
- **#3: `MkdirAll(parent)` + `Mkdir(leaf)` to detect creation, over Stat-then-MkdirAll.**
  The creation decision comes from the syscall result, so no race window exists.
  Intermediate parents are still not chmodded. Reversal: chmod unconditionally as before.
- **#13: exclude the current file from `FileByFormatHandler` pruning, over requiring
  time-sorted generator names.** The clamp to 1 makes the lexical prune delete the file
  just written for any non-sorted generator. Reversal: drop the `current` argument.
- **Umask test in a build-tagged file, over dropping the umask claim.** The umask is the
  stated reason for the explicit chmod; pinning it needs a process-global mutation, which
  only a serial top-level test can do safely.

## Deviations during execution

- (a) Task 2: the `"a/b"` generated-name case passed on the pre-fix code only because
  `dir/a` did not exist; it was strengthened in the review round (create `dir/a` first,
  assert `dir/a/b.log` is not created).
- (b) Task 3: the four new `TestPruneRotation` cases were written with the fix, because the
  `protectIdx` parameter does not exist on the pre-fix code; the handler-level subtests
  covering the same behaviour fail on the pre-fix code. The stable-name collision test added
  in review was proven by mutation (protecting the pre-loop index makes it fail).
- (c) Task 4 benchmark (`BenchmarkRotatingFileHandler_Write -benchmem`): main 360 B/op,
  4 allocs/op; branch 360 B/op, 4 allocs/op, about 15 % lower ns/op (one write call per line).
  `os.ReadDir` on a 10k-entry folder is about 2.5x faster than the previous two globs.
- (d) Review round 1 (three parallel reviewers) found a data-loss regression introduced by
  Task 2: `verifyFiles` matched the current file by path string, so on a case-insensitive or
  normalising filesystem (APFS, NTFS) a generator yielding `app` then `App` pruned the file
  just written. The current file is now excluded by path equality or `os.SameFile`, and the
  limit is reduced only when an exclusion happened. Regression subtest added (skipped on a
  case-sensitive filesystem).
- (e) Review round 1, security: the `WithTempDirFallback` folder followed a pre-planted
  symlink (`chmod` of the target, logs written into it; pre-existing on main). On `EEXIST`
  the fallback folder is now `Lstat`-checked and rejected when it is a symlink, not a
  directory, or (Unix, `filelogger_unix.go`) not owned by the effective uid; `filelogger_other.go`
  is a no-op stub. The check-then-chmod is not atomic; the residual risk in a non-sticky
  shared `TMPDIR` is documented in the godoc. Caller-supplied folders are unchanged.
- (f) `FileByFormatHandler` also applies `filepath.IsLocal` to the generated name, which on
  Windows additionally rejects reserved device names (`NUL`, `COM1`); recorded in the
  CHANGELOG.
- (g) CHANGELOG: generated-name rejection and surfaced listing errors moved to `### Changed`
  with conditions and a migration note; the temp-fallback fix is under `### Security`.
- (h) Standards audit: P1/P2 grooming applied in-cycle, except R50 (one argument per line) in
  the changed test lines, which is deferred to the planned project-wide standards grooming
  pass (main does not follow R50 in tests either). The subtest named "dot dot" is "double dot"
  because of the `dupword` linter.
